# 会议纪要技能

## 目标
产出一份让人一眼看清"决定了什么、谁来做、什么时候完成"的纪要。

## 工作流程

### 第一步：接收输入
- 用户粘贴转写文本 / 口述要点 / 图片附件
- 若信息过少（缺时间/参会人），先补问一轮再整理

### 第二步：提取与结构化

从原始内容中提取并整理为：

```markdown
# 会议纪要

**时间**：{日期 时间}（用户提供或"待补充"）
**参会人**：{姓名列表}
**主题**：一句话概括

## 决议事项
1. {决议 A — 具体到可执行的程度}
2. {决议 B}

## 行动项
| 事项 | 负责人 | 截止时间 | 备注 |
|------|--------|---------|------|
| 完成 X 的 Y | 张三 | 周三前 | 需协调 Z 资源 |
| 更新文档 | 李四 | 本周五 | |

## 待跟进问题
- {问题 A}：已分配给 {人} 跟进，下次会议汇报
- {问题 B}：暂无结论，需升级处理

## 会议记录（原始要点摘录）
> 按时间线摘录关键讨论，保留原意
```

### 第三步：建入待办（需用户确认）
列出行动项后询问："是否将这些行动项建入待办系统？"

用户同意后：
```
todo_create(text="#会议 !! {事项} @{截止}")
```
速记语法：`#分类`、`!!` 高优先、`@HH:MM` 当天提醒时间、`@YYYY-MM-DD`（或 `@MM-DD` 当年）把事项落到指定日期清单（改期/未来截止用）

### 第四步：可选导出
- `create_document(path="会议纪要_{日期}.docx", title="会议纪要 {主题}", content=纪要Markdown)` → Word 文件
- 直接在对话中展示（默认）

## 质量标准
- 不改变原意；无法确定的信息标注"（待确认）"
- 决议必须具体到可验证（"优化性能"→"首屏加载从 3s 降至 1.5s"）
- 行动项建待办前必须先列出征求用户同意
- 负责人缺失时标注"待指派"而非编造
