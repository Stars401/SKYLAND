# 代码审查技能

## 目标
给出可执行的、按优先级排序的代码修改建议。

## 工作流程

### 第一步：获取代码
- 用户粘贴代码 → 直接进入第二步
- 用户给文件路径 → `read_file(path="...")` 读取
- 用户给目录 → `glob(pattern="**/*.rs")` 定位后逐个 `read_file`

### 第二步：三维度审查

**🔴 正确性（必须修 — 会导致 Bug 或崩溃）**
- 逻辑错误（条件反转、边界溢出、空指针解引用）
- 并发问题（竞态条件、死锁）
- 资源泄漏（未关闭文件/连接/锁）
- 错误处理缺失（`unwrap()` / 忽略 `Err`）

**🟡 安全性（建议修 — 存在攻击面）**
- 注入（SQL/命令/路径穿越/XSS）
- 敏感信息泄漏（硬编码密钥、日志打印密码）
- 不安全的反序列化 / 不安全的随机数
- 权限检查缺失

**🟢 可读性（可选 — 提升维护性）**
- 命名不表意（变量/函数/类型名）
- 函数过长（>50 行）或嵌套过深（>3 层）
- 重复代码（可提取公共函数）
- 缺少关键注释（复杂算法的 why）

### 第三步：输出审查报告

对话中直接展示：

```markdown
## 代码审查报告

### 🔴 必须修（{n} 项）
| # | 位置 | 问题 | 修复方案 |
|---|------|------|---------|
| 1 | `file.rs:L42` | 空指针解引用 | 添加 None 检查 |

**修复示例：**
```rust
// 修复前
let val = map.get(key).unwrap();

// 修复后
let val = map.get(key).ok_or_else(|| format!("key not found: {}", key))?;
```

### 🟡 建议修（{n} 项）
...

### 🟢 可选优化（{n} 项）
...
```

### 第四步：可选生成报告文件
若用户需要正式文档：
- `create_document(path="代码审查报告_{日期}.docx", content=报告Markdown)` → Word
- `create_pdf(path="代码审查报告_{日期}.pdf", content=报告Markdown)` → PDF

## 质量标准
- 每条问题必须有：文件:行号 + 问题描述 + 修复代码示例
- 只评论给出的代码，不臆测未提供的上下文
- 严重度排序不可随意 — 正确性 > 安全 > 可读性
