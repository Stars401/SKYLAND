# AI 生图工作流

用户请求生成图片（画图/出图/配图/海报/插画/封面/logo 草图等）时，严格按本流程执行。

## 核心原则

**只用 `generate_image` 工具生图。**
它是系统内置的原生生图管线：自动读取已配置的图片服务商、自动失败重试、自动保存到生图目录（ImgGenerator/）、自动在对话中展示图片卡片。
**禁止**用 bash + curl/wget 手动调用图片 API —— 那条旁路没有重试、没有落盘规范、没有会话展示，是已被淘汰的脆弱做法。

## 执行步骤

1. **理解需求**：从用户描述提炼画面要素。信息不足时（如"随便画一张"），自行选择一个明确主题，不要反问浪费时间。
2. **撰写提示词**：组织成具体的画面描述 —— 主体（是什么、在做什么）+ 风格（写实/插画/水彩/赛博/极简…）+ 构图（特写/全景/视角）+ 光线与色调。中英文均可，要素齐全比语言选择更重要。
3. **调用工具**：
   - `generate_image`，参数 `prompt` = 画面描述。
   - `size` 可选：方图 1024x1024、横图 1536x1024、竖图 1024x1536（按用途选）。
   - `provider` 通常省略（默认取已配置的第一个服务商）。
4. **检查结果**：成功则输出中含保存文件名与访问地址，图片卡片会自动出现在对话里。
   - 失败（如未配置服务商）→ 把失败原因原样告知用户，并指引：到「AI 生图」页完成服务商配置（API Key / Base URL / 模型）后重试。
5. **收尾答复**：必须有一段面向用户的最终文字（不要止步于工具调用），说明：画了什么、风格选择、文件名。

## 多图需求

用户要多张不同的图 → 分多次调用 `generate_image`（每次不同 prompt），全部完成后再统一收尾说明。

## 提示词参考模板

```
[主体]，[动作/姿态]，[环境/背景]，[艺术风格]，[光线]，[色调]，[构图视角]
```

例：「一只戴圆框眼镜的橘猫坐在书桌前敲键盘，深夜书房暖黄台灯，温暖治愈的插画风格，柔和光线，暖橙色调，中景侧视」

## 边界

- 用户要修改/编辑已有图片（而非新画）→ 当前工具链以文生图为主，如实告知能力边界，可用文字描述差异后重新生成。
- 用户要的其实是设计稿/矢量文件 → 说明可先出概念图（位图），矢量源文件需要专业设计软件。

## 失败处理与红线
- generate_image 未配置/报错 → 原样告知失败原因 + 指引「AI 生图」页完成服务商配置（API Key / Base URL / 模型）
- 连续 2 次生成失败 → 停止重试，告知用户建议检查网络与 API 配置
- **红线**：必须给出最终文字说明（画了什么/文件名/风格选择），禁止止步于工具调用
