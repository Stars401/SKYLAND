2. **产物落点**：生成的文件一律写入当前工作目录（或用户在本次请求中明确指定的位置），文件名遵循本技能的命名约定；禁止把产物写到工作区根目录之外或临时目录。
3. **数据边界**：只读取本技能流程声明需要的数据源（如 todo_read / 用户消息），禁止为"丰富内容"而虚构未发生的工作、编造数据或引用不存在的文件。

# 周回顾技能

## 目标
诚实反映一周数据，让用户看清趋势并聚焦下周。

## 工作流程

### 第一步：拉取数据
```
调用 todo_read(scope="recent")
```
获取最近 7 天全部待办事项（含已完成与未完成）。

### 第二步：统计分析

| 指标 | 计算方式 |
|------|---------|
| 完成率 | 完成数 ÷ 总数 × 100% |
| 高优先完成率 | 高优先完成数 ÷ 高优先总数 × 100% |
| 连续拖延项 | 未完成且创建超过 3 天的事项 |
| 日均完成 | 完成数 ÷ 7 |

### 第三步：生成周回顾

```markdown
# 周回顾 — {起始日} ~ {结束日}

## 📊 本周数据
- 总事项：{n} 项 · 已完成：{m} 项 · **完成率：{z}%**
- 高优先完成率：{h}%（高优先 {a}/{b}）
- 日均完成：{avg} 项/天

## ⭐ 亮点
- **{最重要的完成项}**：{一句话成果}
- {其他值得肯定的完成项}

## ⚠️ 遗留（{k} 项拖过 3 天以上）
| 事项 | 拖延天数 | 建议 |
|------|---------|------|
| {事项 A} | {n} 天 | 继续（有明确截止日）|
| {事项 B} | {n} 天 | 拆分（太大，建议拆为 X+Y）|
| {事项 C} | {n} 天 | 放弃（已过时/不再需要）|

## 🎯 下周焦点（不超过 3 件）
1. **{最重要}** — {为什么}
2. {次重要} — {为什么}
3. {其他}
```

### 第四步：可选导出
- `create_document(path="周回顾_{周次}.docx", title="周回顾 {起始日}~{结束日}", content=回顾Markdown)` → Word
- 直接在对话中展示（默认）

## 质量标准
- 诚实反映数据 — 完成率低就写低，不粉饰
- 遗留项必须逐条点名并给出明确建议（不是罗列完事）
- 下周焦点不超过 3 件，超过说明优先级不清

## 失败处理与红线
- 	odo_read(scope="recent") 报错或返回空 → 如实告知「最近 7 天无待办记录」，建议从创建第一条待办开始，不要编造完成率
- 高优先数据不足以计算 → 该指标标注「样本不足」而非硬算
- **红线**：完成率/数量必须来自工具返回值；诚实反映低完成率，不粉饰
