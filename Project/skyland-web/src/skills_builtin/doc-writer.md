## 执行纪律（强制 — 违反任意一条即视为未完成本技能）

1. **严格按本技能的工作流程逐步执行**，不得跳步、不得省略中间产出；流程中声明的每一步都必须有对应的实际动作或输出。
2. **产物落点**：生成的文件一律写入当前工作目录（或用户在本次请求中明确指定的位置），文件名遵循本技能的命名约定；禁止把产物写到工作区根目录之外或临时目录。
3. **数据边界**：只读取本技能流程声明需要的数据源（如 todo_read / 用户消息），禁止为"丰富内容"而虚构未发生的工作、编造数据或引用不存在的文件。
4. **冲突上报**：若用户请求与本技能流程冲突（如要求跳过数据拉取、伪造日期），先说明冲突点并征求确认，未经确认不得擅自偏离。
5. **完成汇报**：结束时必须逐项核对产出物清单，按「做了什么 → 产物在哪 → 遗留/下一步建议」三段式汇报，不得只回一句"已完成"。

# 文档撰写技能

## 目标
根据用户提供的主题和要求，产出一份可直接使用的结构化文档文件。

## 工作流程

### 第一步：需求确认
- 明确文档类型（技术方案 / 产品说明 / API 文档 / 用户手册 / 分析报告 / 其他）
- 明确目标读者（开发者 / 管理层 / 终端用户）
- 明确输出格式偏好：Word（.docx）/ PPT（.pptx）/ PDF / Markdown
- 若用户已说清楚，跳过此步直接写

### 第二步：大纲先行
- 列出一级/二级标题大纲给用户确认（除非用户明确说"直接写"）
- 大纲应覆盖：引言/背景 → 核心内容 → 结论/展望

### 第三步：正文撰写
- 每节 2-5 段；概念先定义后展开
- 代码示例给完整可运行片段并标注语言
- 数据和结论用**加粗**或表格突出
- 术语全文一致；首次出现时给通俗解释

### 第四步：选择工具生成文件

| 用户需要 | 调用工具 | 说明 |
|---------|---------|------|
| Word 文档 | `create_document(path="文档名.docx", title="文档标题", content=markdown文本)` | .docx 格式，自动排版（支持表格） |
| PPT 演示 | `create_presentation(path="演示名.pptx", slides=幻灯片数组)` | 每页一个主题 |
| PDF 文档 | `create_pdf(path="文档名.pdf", title="文档标题", content=markdown文本)` | 适合正式交付 |
| 纯 Markdown | `write_file(path="文档名.md", content=文本)` | 适合代码仓库/知识库 |

**create_* 工具的产物会自动保存到会话工作目录**，用户可在工作目录面板中查看和下载。

### 第五步：保存去向确认
写完后询问用户：
- 文件已生成在工作目录（默认行为，告知路径）
- 如需存入知识库：用 `kb_create_doc` 或 `kb_edit_doc` 写入（用户文档需审批）

## 质量标准
- 标题层级不超过三级
- 每节有明确的信息增量，避免空话和重复
- 关键结论加粗；对比信息用表格
- 面向目标读者调整术语深度

## 失败处理与红线
- create_document/create_presentation/create_pdf 报错 → 原样告知错误原因，同时在对话中输出完整文档正文（保证内容不丢失）
- 用户主题过于宽泛 → 主动列 2-3 个可选切入方向供选择，不要硬写空洞内容
- **红线**：大纲先行（除非用户说直接写）；文档标题与文件名一致；正文完成后必须给出完整路径
