## 执行纪律（强制 — 违反任意一条即视为未完成本技能）

1. **严格按本技能的工作流程逐步执行**，不得跳步、不得省略中间产出；流程中声明的每一步都必须有对应的实际动作或输出。
2. **产物落点**：生成的文件一律写入当前工作目录（或用户在本次请求中明确指定的位置），文件名遵循本技能的命名约定；禁止把产物写到工作区根目录之外或临时目录。
3. **数据边界**：只读取本技能流程声明需要的数据源（如 todo_read / 用户消息），禁止为"丰富内容"而虚构未发生的工作、编造数据或引用不存在的文件。
4. **冲突上报**：若用户请求与本技能流程冲突（如要求跳过数据拉取、伪造日期），先说明冲突点并征求确认，未经确认不得擅自偏离。
5. **完成汇报**：结束时必须逐项核对产出物清单，按「做了什么 → 产物在哪 → 遗留/下一步建议」三段式汇报，不得只回一句"已完成"。

# 工作日报技能

## 目标
产出一份客观、量化、上司可 30 秒扫完的工作日报。

## 工作流程

### 第一步：拉取今日数据
```
调用 todo_read(scope="today")
```
提取：全部事项列表、完成/未完成状态、优先级、分类标签。

### 第二步：合并用户补充
若用户消息中提到了额外工作内容（会议、沟通、临时任务），合并进对应分类。

### 第三步：生成日报

```markdown
# 工作日报 — {日期}

## 今日完成（{n} 项）
- ✅ **{高优先事项}**：一句话说明产出（量化：改了几个文件/修了几个Bug/写了多少行）
- ✅ {常规事项 A}：一句话
- ✅ {常规事项 B}：一句话

## 进行中（{m} 项）
- 🔄 {事项}：当前进度 + 卡点 + 预计完成时间

## 明日计划（{k} 件）
1. {最重要的事}
2. {次重要}
3. {其他}

## 备注
- {需要上级知晓的风险/依赖/求助}
```

### 第四步：可选导出
- `create_document(path="工作日报_{日期}.docx", title="工作日报 {日期}", content=日报Markdown)` → Word 文件
- 直接在对话中展示（默认）

## 质量标准
- 能用数字就用数字（"修复 3 个 Bug" 而非 "修了一些 Bug"）
- 不虚构未提及的细节；信息不足先向用户确认
- 明日计划不超过 3 件，按优先排序
- 高优先完成项加粗，让扫读者第一眼看到

## 失败处理与红线
- 	odo_read 报错或返回空 → 如实告知「今日无待办数据」，基于用户口述内容单独生成日报，不要虚构统计数字
- 用户未补充额外工作内容 → 明日计划版块标注「待补充」而非留空或编造
- **红线**：日报必须以面向用户的文本回复结束（禁止只调工具不说话）
