# 翻译润色技能

## 目标
产出忠实原文、术语准确、格式完整的译文或润色稿。

## 工作流程

### 模式判断
根据用户消息自动判断（不确定时先问）：
- **翻译**：中→英 或 英→中
- **润色**：保持原语言，提升表达质量

### 翻译模式

**规则：**
1. 先输出完整译文
2. 专业术语首次出现时括号附原文：`上下文窗口（Context Window）`
3. **保留原文的 Markdown 结构**（标题层级、列表、引用块、分割线）
4. **代码块、数学公式（$...$ / $$...$$）、URL、文件路径不翻译**
5. 数字与单位按目标语言习惯（中文用万/亿，英文用 K/M/B）
6. 文化差异适当本地化（"as easy as pie" → "轻而易举"而非"像吃派一样简单"）

**输出格式：**
```markdown
## 译文

{完整译文}

---
*术语对照：*
- Context Window → 上下文窗口
- Token → Token（保留）
```

### 润色模式

**规则：**
1. 先输出润色稿
2. 附上不超过 3 条修改说明（改了什么、为什么改）

**输出格式：**
```markdown
## 润色稿

{润色后的完整文本}

---
**修改说明：**
1. {改了什么} — {为什么}
2. {改了什么} — {为什么}
```

### 可选导出
翻译/润色完成后询问是否需要文件：
- `create_document(path="译文_{文件名}.docx", title="译文 {文件名}", content=译文Markdown)` → Word
- `create_pdf(path="译文_{文件名}.pdf", title="译文 {文件名}", content=译文Markdown)` → PDF
- 或直接在对话中展示（默认）

## 质量标准
- 不增删原意（润色只改表达不改信息量）
- 列表/标题/代码块/表格的格式完整保留
- 术语全文一致（第一次定了译法后面不换）

## 失败处理与红线
- 用户没给原文 → 请用户提供文本，不要自行写一段来翻译/润色
- create_document/create_pdf 报错 → 原样告知错误原因 + 已在对话中输出完整译文（信息不丢失）
- 代码块中的注释 → 翻译注释、保留代码本身
- **红线**：代码/公式/URL/路径永不翻译；润色不增删原意
